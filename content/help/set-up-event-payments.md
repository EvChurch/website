## Choose the event template

In Rock, use a registration template configured with **Blink Pay** as its financial gateway. The former Simple Donation event templates have been migrated to BlinkPay. Keep using the appropriate template for the event; its questions, prices and financial account still belong to that event.

Simple Donation has been cancelled. Do not select it when creating or copying a template. If creating a new paid template, select **Blink Pay**. This gateway supports one-off NZD bank payments; it does not support cards, saved accounts or automatic instalment plans.

## Check each registration instance

On the event's registration instance, select **Blink Pay** for **BlinkPay connection** and **NZD bank payments** for **BlinkPay payment route**. Check these selections even when copying an existing event. These fields select the payment gateway; keep the event's correct financial account separately.

Check prices, registration dates and any minimum payment before publishing. Free events do not need a payment gateway. An event with optional paid tickets still needs the BlinkPay connection and route.

## Check the attendee journey

Open the public registration link and check its questions and total. A paid checkout should show **Continue to bank**, then BlinkPay with **Pay Ev Church**, the correct amount and event payment particulars. See [Pay for an event by bank](/help/pay-for-an-event).

Existing balances use the same event template and instance configuration. Keep historical transactions intact. If a payer reports a debit without a completed registration, ask finance to reconcile the original payment before arranging another attempt.
